# Projects Preparing v375 — Stage sign-off

1. Back up the production database as usual. Run `sql/2026-11-10-preparing-stage-closures-v375.sql` in Supabase SQL Editor before deploying the code. The migration adds one table and a private Storage bucket; no existing tables/data are rewritten. If a bucket with the same name already exists, verify that it is private. The API refuses to use a public bucket.
2. Replace the matching files in `EmptyCanvas/next-frontend` and deploy through the existing workflow. No new environment variables or npm packages are required. Existing Supabase service-role credentials are used.
3. In a test project, open each of the five Project Steps, choose Close Stage, upload signed images, verify the previews, check the confirmation and save. Reopen the stage to verify the actor, Cairo timestamp and document images. Confirm a user without stage access cannot read or close it.

Design decisions: this is a formal, immutable sign-off record, independent of the physical quantity progress. Closing does not set progress to 100%, block quantity edits, close the school, or automatically close the project. It does not require 100% quantity progress. There is no reopen/delete action in this version. Each stage can be signed off once per project. A closure requires 1–10 JPG/PNG/WEBP images; the combined uploaded size is capped at 3.5 MB to fit the existing deployment's request limits. Large images are resized if needed, so inspect previews before confirming. Documents are served through an authenticated ERP route. The project progress API exposes only closure booleans, not names or files. The existing separate school workflow is unchanged.

Tests: `node --test tests/projects-preparing-v375-stage-closures.test.mjs` (6 mocked service/contract tests); full Projects Preparing suite 304/305, one pre-existing v246 assertion expects no school-search input anywhere, but v374 intentionally introduced one inside Add School. No live Supabase migration, production deployment, browser run, or real upload was performed in this environment.
